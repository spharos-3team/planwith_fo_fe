# 커뮤니티 모임 상세 페이지 레이아웃 개선 프롬프트

````text
planwith_fo_fe에서 `/community/meeting/[meetingUuid]` 모임 상세 페이지 레이아웃을 개선해줘.

【목표】
현재 화면은 좌측 본문 영역이 넓지만 방장 프로필 카드만 크게 차지하고, 우측 360px 사이드바에 목적지·여행 기간·모집 인원·참여 상태·CTA가 모두 쌓여 정보 밀도가 과도하다.

방장 프로필은 보조 정보로 재배치하고, 사용자가 모임을 판단하고 신청하는 데 필요한 핵심 정보를 더 빠르게 이해할 수 있도록 개편해줘.

【대상 파일】
- `src/features/meeting/components/MeetingDetailPage.tsx`
- 필요한 경우 모임 feature 내부에만 작은 전용 컴포넌트를 추가 가능
- API, 타입, 서버 응답, 신청/승인/채팅/방장 관리 로직은 변경하지 말 것
- 다른 라우트의 레이아웃과 스타일은 변경하지 말 것

【필수 사전 확인】
1. `README.md`의 「시안 퍼블리싱」
2. `.cursor/rules/design-system.mdc`
3. `.cursor/rules/image-publishing.mdc`
4. `.cursor/rules/code-quality.mdc`
5. `src/app/globals.css`
6. `src/components/common/Button.tsx`, `Badge.tsx`, `ProfileAvatar.tsx`
7. 현재 Next.js 버전에 맞는 `node_modules/next/dist/docs/` 관련 가이드

Figma MCP는 사용하지 말고, 첨부된 현재 화면을 문제 분석 참고용으로만 사용해줘.

【권장 레이아웃】
```text
[ breadcrumb ]

[ 커버 이미지 + 모임 상태 + 모임 제목 ]

[ 목적지 ] [ 여행 기간 ] [ 참여 인원 ]
  └─ 히어로 바로 아래의 가로형 핵심 정보 요약 카드

┌──────────────────── 넓은 본문 영역 ────────────────────┐ ┌─ 참여 패널 ─┐
│ 모임 소개                                                │ │ 참여 현황   │
│ 소개 본문                                                │ │ 진행률      │
│                                                          │ │ 상태 안내   │
│ 방장                                                     │ │ CTA         │
│ [아바타] 닉네임 · 방장                                   │ └─────────────┘
│          프로필 소개                                     │
└─────────────────────────────────────────────────────────┘
```

【구현 요구사항】

1. 핵심 정보 요약
- 기존 우측 사이드바의 `여행 목적지`, `여행 기간`, `모임 인원` 정보를 히어로 바로 아래로 이동해줘.
- 데스크톱은 3열 카드/정보 영역으로 표현해줘.
- 각 항목은 라벨과 값을 명확히 구분하고, 기존 `destination`, `period`, `memberCountLabel` 계산값을 그대로 사용해줘.
- 구분선 또는 적절한 간격으로 스캔하기 쉬운 구조를 만들어줘.
- 새로운 raw hex는 쓰지 말고 기존 semantic token을 사용해줘.

2. 본문과 방장 정보
- `모임 소개`는 메인 콘텐츠로 충분한 폭을 확보해줘.
- 소개 하단에 방장 정보를 배치해줘.
- 기존처럼 방장 프로필만을 위해 큰 빈 카드가 생기지 않도록, 아바타·닉네임·방장 Badge·소개를 중심으로 밀도 있게 구성해줘.
- `ProfileAvatar`, `Badge`를 재사용해줘.
- 소개가 없을 때도 불필요하게 큰 빈 공간이 생기지 않게 처리해줘.

3. 우측 참여 패널
- 데스크톱에서 우측 패널은 `lg:sticky`를 유지하되 폭은 약 320~340px로 조정해줘.
- 패널에는 아래만 남겨줘.
  - `참여 멤버` 제목 및 현재 상태
  - 진행률 바
  - 신청/승인/완료 상태에 따른 안내 문구
  - 상태별 행동 버튼
- `모임 신청`, `승인 대기중`, `채팅방 입장`, `모임 구성원 보기`, 방장용 구성원 관리/수정/관리 액션 등 기존 조건부 분기와 기능은 모두 유지해줘.
- 버튼은 가능한 한 기존 `Button`을 사용하고, Link CTA는 기존 디자인 시스템의 버튼 스타일과 시각적으로 일관되게 맞춰줘.
- `모임 나가기`는 보조 행동으로 유지해줘.

4. 반응형
- 모바일과 태블릿에서는 히어로 아래 핵심 정보 요약을 1열 또는 2열로 자연스럽게 전환해줘.
- 본문과 참여 패널은 한 열로 쌓아줘.
- 모바일에서는 sticky를 해제해줘.
- 정보 순서는 `핵심 정보 → 모임 소개 → 방장 정보 → 참여/행동`을 기본으로 해줘.
- CTA가 작거나 눌리기 어려워지지 않도록 기존 버튼 높이 규칙을 지켜줘.

【디자인 시스템 규칙】
- `Button`, `Badge`, `ProfileAvatar` 등 기존 공통 컴포넌트를 우선 사용.
- `text-heading-*`, `text-body-*`, semantic color/radius/spacing 토큰을 우선 사용.
- 한 화면 때문에 `globals.css` 전역 토큰을 수정하지 말 것.
- raw hex, 불필요한 arbitrary color, feature 내부에 중복 버튼 컴포넌트 생성 금지.
- 페이지에서 `SiteLayout`, Header, Footer를 직접 import하지 말 것.
- API 호출 방식과 React Query query key는 변경하지 말 것.

【검증】
- 변경 후 `npm run lint`
- `npm run typecheck`
- `npm run build`
- 실패 시 원인을 확인해 수정하고, 기존 환경 문제라면 구현 문제와 구분해 보고해줘.

【완료 보고 형식】
1. 변경한 파일 목록
2. 정보 구조가 어떻게 바뀌었는지
3. 반응형 동작
4. 검증 결과
5. 남은 주의사항(있다면)
````
